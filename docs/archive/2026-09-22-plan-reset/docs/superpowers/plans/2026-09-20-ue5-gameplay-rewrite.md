# UE5 彩能游乐场玩法整体重写计划

## 目标

把 `Unreal/CainengPlayground` 从官方 First Person / Shooter 示例玩法逐步改为已确认的“彩能游乐场”设计。重写包含规则、移动、喷涂、武器、技能、比赛目标、狂欢事件和结算，不是只改武器参数或继续延长中继试炼。旧代码和地图先保留，待新循环替换并验证后再决定哪些模板部分移除。

## 架构约束

- **规则层**：无 Actor/Widget/资产依赖的确定性函数，自动化覆盖边界条件。
- **运行层**：小型 UE ActorComponent/Subsystem 执行移动、命中、计时与状态复制；不让 Character 或 GameMode 成为所有玩法的巨型脚本。
- **定义层**：`UPrimaryDataAsset`/`UDataAsset` 定义武器、技能、角色玩法参数、表面类型、公共目标和事件参数。
- **表现层**：`UWeaponPresentationDefinition` 与 `UCharacterVisualProfile` 控制 Skeletal/Static Mesh、材质、动画/重定向、VFX/SFX 挂点；不把模型引用写进玩法规则。缺少适配动画时允许使用通用动作，不阻塞替换模型。
- **输入边界**：鼠标直接移动视角，不依赖按住右键；键鼠只是初期方案，之后由同一命令接口接 Bot/手柄。
- **测试顺序**：规则自动化 → C++ 构建 → PIE 可见 → 人工玩法；每层证据单独记录。

## 迭代

### A. 规则核心

1. 定义六种彩能表面、交互状态效果、叠加策略与欢乐行为事件。
2. 明确状态效果非致命、具有时长上限/解除规则；定义泡泡化和 3 秒回场窗口。
3. 定义比赛阶段、公共目标与狂欢事件状态转换的纯规则。
4. 测试错误输入、边界、重复、超时、效果互斥/叠加和状态复位。

### B. 可替换的内容架构

1. 建立玩法武器定义与外观呈现定义的独立资产类型。
2. 建立统一 `ToyWeaponController`、发射/命中接口和 `InteractionResolver`。
3. 角色拆分玩法定义、移动/技能组件、外观档案；允许完全不同的 Skeletal Mesh 和骨架经表现适配替换。
4. 角色与 Bot 共用输入命令/移动/互动接口。

### C. 可玩垂直切片

1. 先落地棱花喷绘器：宽容喷射、表面标记、弹跳花与低门槛反馈。
2. 实现液态、弹跳、飘浮三种表面和移动状态；扩展类型的插槽保留。
3. 加入泡泡回场、安全重生点和简易的非致命对手互动。
4. PIE 实测标准鼠标观察、WASD、跳跃/滞空/冲刺、喷涂和效果解除。

### D. 完整比赛内容

1. 以数据定义接入另外五把玩具武器。
2. 接入六种主动技能和三种轻量移动特性。
3. 完成欢乐值、可选公共目标、狂欢槽、至少三个狂欢事件和 6–8 分钟比赛流程。
4. 实现结算多维称号；击杀不能成为唯一奖励维度。

### E. 六人本地原型与联机

1. 建立可复现的五类 Bot 行为，和真人走同一玩法接口。
2. 人类玩家 + 五 Bot 跑一整局，调节事件节奏、目标参与度和回场频率。
3. 本地循环稳定后验证两客户端；玩法关键状态由权威端裁决，视觉表现可预测。

## 本轮起点与非目标

- 当前自动化 3/3 通过的是旧中继顺序/越梁/出口规则，不计入新玩法规则验收。
- 目前没有完成新玩法的 PIE 验证；本轮从规则核心开始。
- 不在此阶段做正式 UI、人物/武器/地图高模或美术精修；仅维护必要的中文原型反馈。
- 不清理历史 Unity 文件、未提交改动或旧灰盒资产，不自动提交 Git。

## 本轮第一批验收

- 叠加规则 deterministic，超时归零，强控持续时间受到配置限制。
- 泡泡重生在 3 秒门槛前不可执行、到时可执行，且规则不扣欢乐值/永久资源。
- 正向行为可各自产生欢乐值，常规击杀/伤害不成为默认得分事件。
- UE 自动化测试、项目构建通过；随后进入下一轮表现层接入。
