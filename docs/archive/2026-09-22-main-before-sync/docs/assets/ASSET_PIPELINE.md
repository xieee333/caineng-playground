# 资产制作与 AI 交接规范：Blender + Hyper3D + UE

> 更新：2026-09-21。状态：流程设计完成，实际生成、模型加工、绑定及 UE 导入均尚未验证。
> 给不掌握之前聊天的开发者和 AI：按本文分工执行，不把 AI 生成模型直接视为可交付游戏资产。
> 先看 [项目总纲](../MASTER_PLAN.md) 与 [实时进度](../PROGRESS.md)。本文是资产专项，文档分工以总纲第 13 节为准。

## 1. 先理解我们要做什么

项目工作名“异常街区”。一次实验事故改变了人物、设备和科研社区，玩家使用异常枪械、异能与道具进行对战，之后可切换到试跑等模式。

美术参考是用户上传的发明家人物：银灰头发、绿色护目镜、金属外套、略夸张五官，周围有小机器人与实验设备。目标是精致风格化 3D，保留光照体积、布料/金属/玻璃材质层次，以及成年角色的个性和职业感。

不沿用二维动漫、平涂描边、波普网点或 v11 图。也不做婴儿比例、廉价塑料玩具、糖果枪大战。完整画风与玩法见 [当前设计](../superpowers/specs/2026-09-21-anomaly-district-design.md)。

## 2. 工具分工

| 工具 | 本项目职责 | 不能据此认为完成的事情 |
|---|---|---|
| Hyper3D / Rodin | 基于设定图生成模型初稿，探索轮廓、材质及静态道具 | 生成成功不代表拓扑、绑定、机械分件、碰撞或 UE 性能已合格 |
| Blender | 调整造型、修网格、拆分部件、UV、材质、骨骼权重、动作、导出 | Blender 预览好看不代表 UE 光照和动画一定正确 |
| Unreal Engine | 导入资产、配置材质与动画、碰撞、枪口和握持点、验证游戏表现 | UE 内有模型不代表联网功能、手感或性能已经验收 |

Blender 是主要加工工具。Hyper3D 是可选加速途径，可以在不省时或质量不够时改为 Blender 直接建模。UE 验证是资产交付的必要环节。

官方资料说明 Rodin 提供图像/文字生成、常见格式导出，以及 Blender/UE 相关插件入口。实际可用功能、插件兼容性和账户权益须在执行当天核实；本项目没有实测这些插件。

## 3. 按资产类别决定怎么做

| 类别 | 建议策略 | 必查问题 |
|---|---|---|
| 主角 | 完整设定后尝试生成，再用 Blender 精修；必要时直接制作基础角色 | 脸、手、肩肘膝网格、握枪、动作变形、角色辨识度 |
| 核心武器 | 先画清功能结构，再生成外形参考或初稿，活动零件在 Blender 制作或重做 | 部件不能黏成一块；枪口、握把、旋转/伸缩轴正确 |
| 小型静态道具 | 优先用于测试 Hyper3D 是否节约工时 | 底面、背面、比例、材质、网格密度与碰撞 |
| 模块化建筑 | Blender 统一尺寸直接制作主体，生成工具可补局部装饰 | 拼接缝、门高、通道宽度、网格对齐、重复使用 |
| 机关与移动掩体 | 按玩法尺寸做规则网格，外观与碰撞分开 | 轴心、运动范围、碰撞卡住、玩家可读性 |

不要先批量生成一堆资产再决定用途。每件资产先有用途、尺寸、活动部件和验收标准。

## 4. 参考图片必须能跨电脑找到

本轮参考图原始文件名为 `f53798028fe11627bd62419300d7bd11.png`，来自聊天附件；此前路径位于微信临时目录。该路径不是可靠的长期资产位置，本文不声称图片已保存进仓库。

开始人物制作时：

1. 检查仓库是否已有经授权保留的原参考图，记录真实路径。
2. 原文件存在且当前任务授权使用时，把项目参考副本保存到 `art/references/inventor-style/`，登记来源与参考用途，不覆盖原图。
3. 缺失时请用户重新提供；可以继续灰盒和工具准备，但不能假称已按原图校准视觉。
4. 参考图只展示了部分人物，不能确定完整下半身、背面与手部结构。先设计我们自己的正、侧、背面和完整服饰。
5. 准备生成输入时让角色与背景、机器人分离，尽量保持姿势与比例一致。模型对遮挡区域的补全属于推测，需要人工检查。

不要把参考人物原样复刻成默认主角。借鉴造型与材质语言，制作与本项目身份、技能一致的原创设计。

## 5. 首次流程测试顺序

### A. 一件简单静态物件

先选一个实验仪器，或没有复杂关节的小机器人静态摆件。确定正面轮廓、背面、尺寸和颜色，再尝试生成。

导入 Blender，检查六个方向，修补底部和背面，统一大小、材质、轴心，清理隐藏多余几何。导出后在 UE 标准光照与场景光照下查看。

记录生成耗时、实际费用/额度、修整时间、导入修复时间、最终效果。只有总成本有优势才扩大使用；不凭宣传截图判定能否量产。

### B. 第一把矢量脉冲器

拆成机身、握把、枪口环和活动配重。明确哪一部分旋转、哪个轴伸缩；生成初稿若分件错误，在 Blender 重新制作机械部分。

用占位角色检查握持姿势、视角遮挡、枪口位置与开火动作。功能上先测推走掩体、打偏炸弹，外观要能解释这些动作。

### C. 第一个发明家角色

静态物件和武器流程验证后，再投入角色。先全身设定，再处理基础网格、服装、头发和配件。用明确的中立姿态制作绑定，避免将图片里的托腮姿势当作角色绑定姿态。

跑跳、举枪、冲刺与受击都通过后，再扩展表情、皮肤和第二角色。

## 6. 每件资产的操作流程

1. **写简短任务卡：** 用途、风格、尺寸、静态/骨骼、活动零件、预期画面距离、碰撞需求。
2. **准备设定图：** 至少看清整体轮廓；对不可见结构做明确设计，生成之前解决明显矛盾。
3. **选择方法：** Hyper3D 初稿或 Blender 直接制作。没有额度/接口时仍可做设定与手工灰盒，不编造生成结果。
4. **保存原始输出：** 记录任务 ID、输入、参数、导出格式、时间与实际费用；凭据不写进文件或 Git。
5. **Blender 加工：** 检查拓扑、法线、重叠、UV、材质、尺寸、部件、轴心，保存可编辑 `.blend`。
6. **角色或机械动作：** 角色处理骨骼权重，机械按需要分件或绑定；检查极限姿态穿插。
7. **导出候选：** 静态初稿可用 GLB 交换，进入 UE 的静态/骨骼资产优先试 FBX；格式不能保证材质与骨骼无损，按锁定的软件版本验证。
8. **UE 集成：** 验证尺寸、朝向、材质、碰撞、动画、插槽和游戏镜头下辨识度。碰撞由简单形状优先承担，不照搬高密网格。
9. **记录并决定：** 通过、返修或弃用。保留发现的问题和下一个具体操作，更新进度。

尺寸以 UE 中厘米为统一约定。Blender 单位可按工作习惯设置，但先用一个已知 100 厘米的测试立方体验证导入尺寸；不盲目对已经绑定或有动画的对象应用缩放。

面数、纹理尺寸和 LOD（远处简化模型）预算在目标机器与同屏规模明确后实测确定。不要默认所有资产都上最高分辨率，也不要把 Nanite 当作所有角色和透明材质问题的解决方案。

## 7. 验收清单

- [ ] 风格：与新的发明家参考和研究站材质语言一致，没有误用旧漫画基线。
- [ ] 静态：正背侧顶底均检查；无明显破洞、翻面、黏连、悬空零件。
- [ ] 比例：UE 中尺寸正确，门、手、握把、枪口等关系合理。
- [ ] 角色：肩肘膝弯曲、跑跳与握枪自然；没有明显权重拉扯和穿插。
- [ ] 机械：活动部件独立，轴心正确，动作不穿插机身。
- [ ] 材质：在 UE 内检查金属、粗糙度、法线和透明；不只看生成平台预览。
- [ ] 碰撞：玩家不会卡住，枪口不在角色身体内，机关不会把人永久夹住。
- [ ] 性能：记录三角形数量、材质槽、纹理大小，并在目标场景实测。
- [ ] 来源：原始输入、生成记录、第三方素材来源和使用权限可追溯。
- [ ] 交付：可编辑源文件、导出文件、UE 资产和测试记录相互对应。

未执行的项写“未验证”，不能勾成通过。生成服务返回下载链接只代表初稿可下载。

## 8. 目录与命名建议

下列为未来创建目录，不表示其中资产已经存在。

```text
art/references/inventor-style/          新风格参考及来源记录
art/source/props/LabDevice01/           原始输出、加工后的 blend、贴图
art/source/weapons/VectorWeapon/        分件武器源文件
art/source/characters/Inventor01/       角色源文件与动画
art/exports/                           准备导入 UE 的候选文件
docs/assets/records/                   每个资产的过程与验收记录
unreal/CainengPlayground/Content/Caineng/Art/  UE 内资产
```

命名示例：`LabDevice01_v001_raw.glb`、`LabDevice01_v002_clean.blend`、`LabDevice01_v002_export.fbx`。不覆盖原始生成版本。UE 命名建议静态模型 `SM_`、骨骼模型 `SK_`、材质实例 `MI_`、纹理 `T_`。

建立 Git LFS 后再提交大模型和纹理，确认远端配额。缓存、生成临时文件和大型构建产物不默认入库。另一台电脑需安装匹配版本并拉取 LFS 实体文件。

## 10. 接手 AI 的下一步

本文建立时仅要求写文档，没有启动付费生成。未来接手按当次用户任务判断授权；真正开始资产制作时，先核实参考图、Blender/UE 环境和 Hyper3D 可用性，再完成“一件实验仪器 → Blender 修整 → UE 查看”的小测试。该流程属于总纲 A0 支线，P5A 批量资产前必须验证。

执行生成前核实当次授权、费用和输入是否可上传；不要把使用工具的意向理解为无限额度。无接口时可使用已安装工具或手工流程，不声称具备未发现的自动化能力。

本方案不要求一开始购买长期订阅，也不要求所有资产都通过 AI 生成。是否继续用 Hyper3D，依据试验记录的总成本与质量决定。
