# 异常街区｜项目总纲

更新：2026-09-22。现行规划仅本文和 [首交付计划](FIRST_DELIVERY.md)。用户最新确认B方向：枪体自带鲜明属性，玩法围绕枪械展开，不要求喷涂占地。归档不是实施依据。

## 1. 产品核心

第一人称、精致风格化3D、2–4人私人房间的娱乐对抗。枪械是主角，不是完成资源任务的辅助工具。射击本身有趣，对人、环境和兼容物体产生符合属性的不同效果；技能与目标帮助发挥枪械，不能取代它。

设计顺序：枪械属性→单枪对抗→双枪配合→相应场景→简单比赛目标→辅助技能→验证后扩展。低瞄准门槛同时保留判断与操作空间；预判、诱导、反制和翻车形成乐趣。不做无限连控、长时间失去操作、大逃杀淘汰或永久战力养成。

小交付也必须有完整必要UI、统一画面、动作音效与独立运行包，不是一次性功能展示。允许调参和正常迭代，不承诺零返工；多人、表现分离和可配置基础从首版建立。单人为练习，不冒充多人乐趣。

## 2. 世界与视觉

科研社区事故产生异常材料，居民利用其改装工具，举行对抗试验。冲量、弹性、金属耦合、光学残留是可选原理，不是已确定四枪。武器造型、声音、命中与场景作用来自同一属性，不能用互不相关的技能凑数。

人物帅气、动漫化五官、清楚发束与职业感，环境有生活痕迹和维修设备。精致风格化3D，克制塑料感和写实强反射，不幼儿化。参考用户指定的中间绿发人物整体语言，不直接复制形象。参考图：`docs/concepts/character-style-reference-greenhair-2026-09-20.png`。

UI、场景、角色和枪械先做同屏提案供用户集中确认，必要玩法反馈不等正式美术才制作。采购、付费生成与外部上传需授权，素材商用许可和技术质量均需核实。

## 3. 枪械设计标准

每枪确定核心属性、基础攻击、属性操作、对人效果、环境对象白名单、代价、反馈和反制。必须能独立正面对抗，并有不止纯伤害的战术用途。

| 候选属性，尚未锁定 | 用途方向 | 限制 |
|---|---|---|
| 弹性 | 反弹射击、改变落点、弹跳追逃 | 结果可预判，不长时间失控 |
| 牵引 | 短促拉偏、拉动指定掩体 | 不长期锁人、不隔墙偷取 |
| 冲量 | 定向推离、推掩体、打偏兼容物 | 有代价和防连续控制，不只有光效 |

这些是候选，不是用户已选定的新枪。现有矢量/凝胶是可复用技术，不决定最终身份。先用同场景比较两种有显著差异的属性；不能把弱枪仅换外观就算第二套玩法。

一致的属性规则让玩家自己发现用法，但不承诺万物可交互。强效果有前摇、资源或位置代价，受害者能躲、破解或利用结果。不能用秒杀来掩盖枪械无趣。

## 4. 比赛与技能

主目标由双枪切片结果决定，可比较简单区域争夺与直接对抗；目前不锁定胜负规则。停止默认样本搬运/封存经济，也不强制喷涂占地。目标促进枪械碰面和使用，不让跑腿、交付或等待成为主体。

小丑盒子式预判和诱导保留，优先从枪械延迟效果、弹道或场地作用产生。独立伏贴、残像只有增强枪械时才接入，不能因为曾写过就成为必做。首交付保留至少一个辅助技能目标，具体功能待双枪验证后选择。

允许藏身与绕路，不强制敌人雷达。不用反向鼠标、长时间黑屏和无法应对的连控。线索需视觉/声音互补，不能仅靠听觉或精准枪法反制。快速复活减少旁观时间。

运输、校准、实体组件藏放、多角色与更多地图进入待评估扩展池，不是必须照单实现。用户提出的方向保留；扩展需证明增强核心再排期，不以堆系统代替乐趣。

## 5. 地图与表现

首图是一块维修街区，有环路、转角、可达阳台和少量指定互动掩体。根据枪属性确定表面与物体，不先铺空城。关键位置至少两条普通路线，装备提供优势而不是参与资格。尺度按2/3/4人遭遇密度实测。

命中、反弹、位移、失效、能量不足必须可读，外观不能暗示不存在的交互。第一人称不强制翻滚镜头；本地手臂和远端角色协调。枪械、环境、UI和声音使用统一视觉语言。

## 6. 可扩展实现与效率

审计后复用UE工程、房间、伤害、复活和测试基础，旧包通过不等于新模式通过。武器行为、模式、角色能力、地图对象、外观和UI分开。武器采用稳定ID与配置，特殊属性允许独立实现，不造万能框架。

服务器裁决命中、资源、冷却、状态和得分，客户端请求/展示；首批做多人，不先单机后重写。地图对象可摆放，不散落硬编码坐标；UI读装备状态，不写死两枪名称。外观与判定分离，换骨架仍需握持和动画适配。

扩展验收：测试武器配置可进入装备/HUD；替换资源或互动对象不改角色；替换测试网格不改伤害。测试内容不算正式第三枪。只为明确方向留接口，不提前开发插件平台。

同批合并构建和定向回归，Computer Use用于必要输入/镜头/视觉检查。自动化验证规则，多进程验证复制，真人验证娱乐性。统一素材/材质与基础动作提高效率，原创重点用于枪械、人物与关键反馈。

## 7. 完整路线与交付

1. 工程审计、属性候选比较、UI/美术同屏提案。
2. 双枪切片：单独好玩、组合有效、对手有反制。
3. 据此锁一个简单模式和辅助技能，做从菜单到结算重开的完整流程。
4. 完成统一表现、设置引导、2–4人测试与Windows小包。
5. 真人反馈后扩枪、角色、地图和适合的成长；不强制恢复旧经济。
6. 公网私人房间、性能、兼容性、干净电脑与分发完善。商业上架另需平台、许可和发布准备。

局域网通过不等于公网可用，成功打包不等于上架完成。交付包括完整运行目录、版本、连接/操作说明、已知问题、日志与配置位置、可重复构建流程。

总纲维护产品边界，首交付计划维护任务与状态。不要新增平行TODO和覆盖版。工时根据实做估计，不报假百分比；新需求先评估核心价值及是否扩大首版范围。
