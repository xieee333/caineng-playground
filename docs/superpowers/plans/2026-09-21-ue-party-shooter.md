# 彩能游乐场 UE 实施准备与阶段计划

> 本文件面向后续开发者和 AI 接手者。它是工程建立前的阶段计划，不是已可执行的完整代码清单。逐阶段实现时使用 executing-plans 的任务跟踪方式；不因本文件自动启动子代理或创建工程。

**目标：** 用 Unreal Engine 验证 4 人怪枪混战，再扩展为 6 人动漫派对射击。

**架构：** 服务器负责伤害、得分、物件归属和机关状态；客户端负责输入与即时视觉反馈。枪械、道具和机关按职责拆分，用数据资产保存参数，优先做最小网络闭环。

**技术栈建议：** UE5、Blueprint（蓝图，可视化逻辑）、必要的 C++、Enhanced Input、CharacterMovement、Niagara、UMG。最终引擎小版本在 P0 用实际安装环境和打包测试固定；本文不要求追随官网默认最新版本。

**对应设计：** `../specs/2026-09-21-party-shooter-design.md`。

## 1. 通俗解释 UE 里各部分做什么

| 游戏里的东西 | UE 对应设计 | 为什么这样安排 |
|---|---|---|
| 玩家跑跳、镜头 | Character、CharacterMovement、SpringArm | 复用基础移动与联网机制 |
| 何时开局、复活、结束 | GameMode | 服务器统一执行规则 |
| 剩余时间和对局阶段 | GameState | 所有人看见相同状态 |
| 每人分数和身份 | PlayerState | 角色重生后分数仍保留 |
| 枪、炸弹、掩体 | 独立 Actor | 能独立生成、同步和销毁 |
| 血量和受击规则 | CombatComponent | 枪械和炸弹使用同一伤害入口 |
| 每把枪的数值 | Data Asset | 调数值不必修改每个角色 |
| 粒子和漫画爆炸 | Niagara | 只表现结果，不独自判定伤害 |
| 界面 | UMG | 展示分数、状态、操作提示 |

先用蓝图实现可读的原型；自定义移动预测、性能热点、复杂规则测试等需要时转到 C++。不把全部逻辑堆在关卡蓝图，也不先引入完整 Gameplay Ability System。若后续技能规模需要它，再做明确迁移评估。

## 2. 工程位置与文件职责

建议将工程放入同仓库 `unreal/CainengPlayground/`。下列路径是计划新增项，本次没有创建任何 UE 资产。

```text

  Config/                         项目设置、输入与碰撞配置

    Core/BP_CPGPlayerState.uasset  分数、统计和身份
    Characters/BP_CPGCharacter.uasset
    Characters/BP_CombatComponent.uasset
    Input/                        输入动作和映射

    Projectiles/BP_PaintProjectile.uasset
    Items/BP_BounceBomb.uasset

    Items/BP_InflatableCover.uasset
    World/BPI_ImpulseReceiver.uasset
    World/BP_BounceSurface.uasset
    World/BP_WheeledCover.uasset
    World/BP_SwingSign.uasset
    Data/                         武器、道具、地图参数
    UI/                           HUD、房间、结算
    Art/                          角色、武器、场景、材质
    VFX/                          漫画粒子、字效
```

`BPI_ImpulseReceiver` 是指定物件接收冲击的统一接口。服务器判断目标类型和位移上限，再调用目标响应；不是对场景中所有东西无条件施加物理力。

## 3. 网络约定：从第一天纳入

服务器就是房间裁判。初期采用玩家主机兼任服务器的 Listen Server，先本机多窗口和局域网验证。互联网好友邀请另需接入会话服务及连通性验证，不能把局域网成功当成公网完成。初期房主退出则结束房间并返回菜单，不做主机迁移。

玩家按开火 → 从自己拥有的角色发请求 → 服务器检查冷却、能量和方向是否合法 → 生成权威攻击 → 计算伤害、击退和得分 → 各客户端显示结果。

客户端可先播放枪口和音效，但不能决定命中伤害。重复请求不得重复消耗、生成或计分。炸弹保存服务器爆炸时间，各机器据此显示倒计时；回扔不能重新计时。

机关同步状态和必要位置，动画从状态推导；不用逐帧广播所有骨骼、粒子或材质。自由物理碰撞在高延迟下难保持一致，因此首轮招牌采用受限摆动，掩体采用受限移动，角色不依靠完整布娃娃物理执行战斗。

普通跑跳使用 CharacterMovement 的网络能力。冲刺和爆炸推动仍需单独验证预测与位置修正；不能假设勾选 Replicates 就自动解决所有互动。

## 4. P0：锁定工作环境和资产管理

- [ ] 检查 UE、编译工具和磁盘空间，记录实际版本与机器配置到 `docs/UE_ENVIRONMENT.md`。
- [ ] 创建第三人称工程于上述目录，运行默认场景，打包 Windows Development 版本并实际启动。
- [ ] 配置 Git LFS：跟踪 `.uasset`、`.umap`、`.fbx`、`.blend`、`.wav` 等大体积二进制；提交 `.gitattributes`。先确认安装与远端配额，不重写现有历史。
- [ ] 忽略 `Binaries/`、`DerivedDataCache/`、`Intermediate/`、`Saved/` 和本地 IDE 文件；保留 `.uproject`、Config、Content 与 Source。
- [ ] 在 `docs/assets/ASSET_PIPELINE.md` 记录厘米单位、统一比例、角色共用骨骼、枪口插槽和素材来源字段。
- [ ] 在 `docs/UE_ENVIRONMENT.md` 写明另一台电脑安装同版本 UE、执行 `git lfs pull` 后的打开和打包步骤。

验收：默认模板能运行、能打包；另一目录的干净检出能获得真实资产而非 LFS 指针。未完成干净检出测试就明确记录未验证。

## 5. P1：两个玩家能正常打一局

产物：Core、Character、CombatComponent、Input、PaintProjectile、L_NetworkLab、基础 HUD。

- [ ] 定义移动/看向/跳跃/开火输入，先保持模板移动，不加入复杂攀墙。
- [ ] 加入服务器管理的 100 点生命、单一测试弹体和命中反馈。
- [ ] 用两个独立进程启动一主机一客户端，双方轮流攻击并记录血量是否一致。
- [ ] 加入服务器计时、一次性击败结算、3 秒重生、出生保护和清除旧角色。
- [ ] 加入 6 分钟结束和原房间重开，验证分数只在开新局时清零。
- [ ] 用网络模拟测试约 100ms 往返延迟和 1% 丢包，记录实际设置与观测，检查重复伤害和复活失败。

验收：两人完整完成一局并重开；主机和客户端的分数、血量、时间一致；同次击败只记一次。记录到 `docs/testing/P1-network-loop.md`。

## 6. P2：两把枪和移动手感

产物：WeaponBase、PaintWeapon、SonicWeapon、武器数据、短冲刺。

- [ ] 将伤害、射速、能量、弹速和击退上限放入数据资产；实现换枪时清理旧计时器和特效。
- [ ] 实现喷绘器宽弹体，以及喇叭近距离扇形判定；两者都做遮挡检查。
- [ ] 实现短冲刺，检查主机/客户端视角下的轨迹与碰撞；失败时先保留普通跑跳，不用视觉瞬移掩盖错误。
- [ ] 为枪口、命中、空枪和受击配置不同的占位声音；提供关闭镜头抖动选项。
- [ ] 在 5、10、20 米距离记录命中率、击败用时及能量消耗，校准有效射程和 3～5 秒击败目标。
- [ ] 测试墙后不受扇形伤害、能量不足不能开火、浮空仍可操作、冲刺不穿薄墙。

验收：玩家不用解释能区分两把枪；双方都有躲避与追击机会。记录到 `docs/testing/P2-weapons.md`。

## 7. P3：三件道具与三种地图互动

产物：Items、World、ImpulseReceiver、道具槽与拾取提示。

- [ ] 实现蹦迪炸弹服务器倒计时、范围遮挡检查、伤害和有限弹起。
- [ ] 实现快递炸弹的地面/持有/飞行/爆炸状态；拾取请求检查距离、视线和空槽；爆炸只能发生一次。
- [ ] 验证两人同时拾取只能一人成功；临爆时回扔不重置时间；断线持有者的炸弹落地继续计时。
- [ ] 实现充气掩体放置检测、生命、10 秒寿命与受限推动；空间不够时拒绝放置且不消耗道具。
- [ ] 实现弹性地块、带轮掩体、摆动招牌，用统一冲击接口连接喇叭和爆炸。
- [ ] 实现连控减弱、环境击败归属与道具总量限制，验证多人同时攻击不会叠出无限位移。
- [ ] 在带延迟的两个进程中重复回扔和引爆各 20 次，检查所有权、时间、位置、得分。

验收：三种道具均可被对手识别和应对；可完成“炸弹弹起→空中开火”和“冲击枪打飞炸弹”组合，没有重复爆炸。记录到 `docs/testing/P3-interactions.md`。

## 8. P4：四人地图与第一轮乐趣测试

产物：L_ComicBlock、出生点选择、拾取点、最小房间界面、结算。

- [ ] 用简单方块搭建三层商业街，设置两条通往高点的路线，标记机关和拾取点。
- [ ] 检查出生点视线与敌人距离；地图过大导致频繁空跑时先缩小距离。
- [ ] 接通创建、加入、离开、满房提示和房主退出返回菜单；最初明确标注为局域网测试。
- [ ] 完成 4 个真实玩家客户端联机，不用机器人代替真人交互结论。
- [ ] 邀请至少 2 位射击新手，与另 2 人连玩 3 局；收集找人时间、击败分布、误操作、失控时间和是否愿意再玩。
- [ ] 完整记录问题优先级：不能玩 → 看不懂 → 不好玩 → 不好看。先修前两类，再判断是否扩充。

验收：满足设计文档第 13 节的初步乐趣标准，且可重复打完并重开。记录到 `docs/testing/P4-first-playtest.md`。未过关就回到 P2/P3 调整，不推进大批资产。

## 9. P5：漫画美术切片和少量内容扩展

- [ ] 在 P0～P2 可并行制作一张静态风格样张；本阶段才批量替换已稳定的碰撞和角色尺寸。
- [ ] 完成一个角色、两把枪、三件道具和一组街区模块的建模、绑定、材质、动画、音效和导入。
- [ ] 优先用材质色块、硬边明暗和可控光照实现漫画感；后处理描边先测透明物件和远景，不预设单一滤镜足够。
- [ ] 加入云游的滑翔技能；验证冷却、落地恢复、空中镜头和网络表现。
- [ ] 在基础体验通过后一次只增加第二组技能、一把候选枪或一组词条，分别试玩后再决定下一项。
- [ ] 为爆炸、危险预警、枪口和命中建立视觉优先级，控制网点和字效对目标的遮挡。

验收：实机画面保持二维动漫观感；武器和道具能远距离辨认；特效开启不影响看清危险。不以概念图代替实机验收。记录到 `docs/testing/P5-art-slice.md`。

## 10. P6：六人、公网与交付

- [ ] 将 4 人扩到 6 人，重新验证出生、密度和性能；无法满足时先保留 4 人。
- [ ] 在已锁引擎版本下选择并接入一个会话服务，测试两处不同网络的创建、邀请、加入、拒绝和掉线提示。
- [ ] 房主退出返回菜单；普通玩家断线后允许重新加入作为新角色，首版不保证恢复原分数，界面说明清楚。
- [ ] 在记录了配置的目标电脑上测 1080p、60fps 目标，即每帧约 16.7ms；分别记录 CPU、GPU 和网络情况，目标未达则降低物件/特效数量。
- [ ] 运行完整对局、多人同时爆炸、极限道具数量和 10 次连续重开测试。
- [ ] 产出带版本号的 Windows 包、操作说明、已知问题、提交号和测试记录；检查另一个干净目录可重建。

验收：至少两处网络的 4～6 人完成实测；性能结果注明机器与画质。公测、专用服务器、收费发布另立计划。

## 11. 风险与取舍

| 风险 | 发现方式 | 首选处理 |
|---|---|---|
| 炸弹、掩体不同步 | 主机与客户端录屏对照 | 减少自由物理，服务器控制状态与运动 |
| 多人画面太乱 | 新手说不清被什么击中 | 降低同时存在数量，突出预警、削减装饰特效 |
| 新手反复被控 | 统计连续失去控制时间 | 缩短控制，加入减弱和脱离机会 |
| 只有一把枪好用 | 武器选择与击败分布 | 调整射程、反制和地图，避免直接叠伤害 |
| 美术成本失控 | 单资产工时持续超预估 | 共用骨骼、模块化街区，先完成单个风格切片 |
| 词条导致碾压 | 改造前后胜率和反馈 | 降低叠加，保留明确代价，必要时移除 |
